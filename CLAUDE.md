# lead_intake

A Frappe app on ERPNext v16. A website enquiry arrives by webhook and becomes a CRM **Lead**. A background job then has Claude fill in the service being asked about, a one-line summary, and a qualification status. Keyword rules take over whenever Claude is unavailable or answers outside the allowed values. A Script Report summarises the pipeline in SQL.

## Hard rules

- **Never print, log or commit** `ANTHROPIC_API_KEY`. It lives in site config or the environment. Error Log entries record the Lead, never the key.
- **Enquiry text is untrusted input.** It is sent to Claude as data, never as instructions. Any value outside the allowed list is discarded and the rules path runs instead.
- **SQL is parameterised.** No string-built queries.
- **Read the DocType before writing code against it.** ERPNext's Lead already has `qualification_status` (Unqualified / In Process / Qualified), `status`, `company_name`, `email_id`, `lead_name` and UTM fields. Confirm field names in `apps/erpnext/erpnext/crm/doctype/lead/lead.json` rather than assuming them.
- **Never overwrite a value a human set.** Triage only fills fields that are blank.

## Honesty rules

- This app was built with Claude Code, and the README says so plainly.
- `docs/BUILD-LOG.md` records who did what as it happens — Armand or Claude Code, what broke, and how it was fixed. Written during the work, never reconstructed afterwards.
- `docs/FRAPPE-NOTES.md` is Armand's own words, written as he learned. Claude Code formats and corrects in clearly marked lines, and never rewords or improves his answers.
- Tests are generated by Claude Code and are never described as written or reviewed by Armand.
- No invented numbers. Real counts are fine.
- Commits carrying `Co-Authored-By: Claude` are Claude-written. Armand's own work is committed without it.

## Environment

Frappe v16 requires **Python >=3.14,<3.15** and **Node >=24**. The bench runs in `frappe_docker`'s devcontainer; the site is `development.localhost`.
